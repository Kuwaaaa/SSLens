Worker 代理 service-worker.ts 代 content script 发 API 和 WebSocket。

职责边界

区域 职责

Content runtime 模块

模块 单一职责

后端结构

API 侧

index.ts 是 Bun.serve router 与 process lifecycle，routes.ts 承担 JSON response、authz 检查、请求解析、SQLite query、row mapper、operator analytics 和 WebSocket publish。

routes.ts 约 31KB REST admin read model

WebSocket 侧

ws.ts 管理 bearer token upgrade、room subscription、presence refcount、Companion presence、短 chat history、emoji/chat rate limit 和内存清理。

presence + companion + throttling in-memory room publish

持久化与安全

db.ts 打开 SQLite 并应用 schema/migrations；auth.ts 负责 EdDSA bearer token；rate-limit.ts 提供轻量内存限流。

small files SQLite EdDSA

Operator console

apps/server/public/index.html 是静态 operator UI，读取 /api/admin/*、/api/status 等接口，不属于扩展 runtime。

共享包

packages/schema

领域类型与验证

定义 Lens、anchor、reaction、reading mode、theme 等共享类型，同时提供运行时 validation。server 与 extension 都应依赖这里，而不是各自复制协议。

packages/url

URL canonicalization

统一 canonical URL 与 roomId 计算。server 用它校验 create Lens 的 url 和 roomId 是否一致，extension 用它进入同一个 page room。

packages/anchoring

锚点创建与恢复

W3C selector 风格的 anchoring 实现，包含 position、quote、fuzzy recovery。它是 surface 层的底层能力，不依赖 React、Chrome 或 server。

职责审计热点

热点 当前混合点 建议边界 优先级
apps/extension/src/content/Overlay.tsx 组合 settings、Lens room、Companion、surface、selection、card open、panel state、bloom trigger。 保持为 composition layer，但可继续把 re-anchor UI state、active card navigation、panel command wiring 拆成小 hook。 中
apps/server/src/routes.ts 请求解析、SQL query、row mapper、权限、业务动作、admin analytics 全在同一文件。 按 domain 拆成 lenses、reactions、reports、admin，保留统一 JSON/error helpers。 高
apps/server/src/ws.ts presence、Companion presence、chat history、emoji validation、rate limit、Bun websocket lifecycle 混在一起。 抽出纯内存模型与 protocol validation，Bun websocket handler 只负责 IO 编排。 中
apps/extension/src/styles.css 全量 overlay、panel、card、companion、theme、animation 样式集中在约 49KB 文件。 若后续样式继续增长，可按 component 或 runtime layer 分 CSS modules/inline blocks；目前不建议为了行数机械拆分。 低
apps/extension/src/service-worker.ts API proxy 与 WS bridge 共存，但都属于 MV3 后台平台适配。 当前可接受；如果增加更多后台能力，再拆 api-bridge 与 ws-bridge。 低

结论

当前 content runtime 的模块化已经明显落地，入口、设置、WebSocket、Companion、surface、Lens room 和 UI 基本分离。下一轮单一职责优化不应再从 content entry 下手，而应优先审计后端 routes.ts 与 ws.ts，再温和收窄 Overlay.tsx 的 composition 责任。
